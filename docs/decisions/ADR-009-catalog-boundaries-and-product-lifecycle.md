# ADR-009 — Catalog boundaries and product lifecycle

**Status:** Accepted for this decision implementation

## Source requirements

The Technical Blueprint locks:

- public category reads and Admin category mutation;
- public product search/detail;
- seller product create/update/delete, image registration, publish and archive commands;
- owning-seller authorization (with Admin delete allowance);
- only ACTIVE sellers may create products;
- Product + Inventory creation in one transaction;
- new products begin DRAFT;
- product lifecycle `DRAFT → ACTIVE → ARCHIVED`, with `SUSPENDED` reserved for admin moderation;
- arbitrary status PATCH is forbidden;
- invalid transitions return a conflict such as `409 INVALID_STATE_TRANSITION`.

## Implementation decisions that are not locked specification

1. **Public visibility.** Only ACTIVE products are returned by public product endpoints. This follows the DRAFT/publish lifecycle and prevents unpublished/archived/suspended inventory from appearing in the marketplace.
2. **Default product currency.** Because the locked create-product example does not include currency while the database requires it, `CATALOG_DEFAULT_CURRENCY` is server configuration. It must be a three-letter uppercase code.
3. **Stable slugs.** Category/product slugs are generated by the backend and are not regenerated on rename. A UUID-derived suffix avoids dependence on name uniqueness.
4. **Product response money.** Product prices are serialized as decimal strings to avoid making binary JS floating point authoritative.
5. **Search/filter MVP.** `GET /products` supports optional text query, category filter, page and limit. Seller listing additionally supports status filtering. More search dimensions are not locked here.
6. **Category mutation.** Category names are 2–200 characters and category parent cycles are rejected. These are catalog integrity choices, not source-locked field limits.
7. **Image endpoint.** The endpoint registers already-produced object-storage metadata. It does not choose S3 vs Cloudinary or invent an upload/signing protocol.
8. **Delete failure.** PostgreSQL referential integrity decides when a product cannot be hard-deleted. The API returns a conflict instead of deleting history or silently changing the request into archive.

## Deliberately deferred

- `PATCH /products/:id/inventory` and inventory mutation rules — this decision;
- object-storage provider and upload protocol;
- admin product-suspension endpoint (not defined by the API list);
- advanced search/ranking;
- Cart/Checkout public Catalog inter-module methods.
